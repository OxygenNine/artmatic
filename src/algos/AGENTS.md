# src/algos/ —— 算法生成器

生成器注册表 + 烘焙 Worker。四种型：`bake`（Worker 烘 sheet 纹理）/
`sim`（固定步长 + 快照 + seek 重放）/ `realtime`（逐帧算）/
`recall`（回放时间轴上过去的整帧 —— 唯一的闪回）。

**何时读我**：加 / 改生成器；动 `sim` 的状态 / 快照 / 步进预算；改生成器**默认值**；
动 `pattern` / `bitmask` 参数时。

相关：`src/core/AGENTS.md`（位掩码位序 · 容量）、`src/audio/AGENTS.md`（音频特征）、
`src/assets/AGENTS.md`（生成器缩略图）、根 `AGENTS.md` 硬约束 1.3。

---

- 二值纹理（元胞自动机）走 **R8**，活性值用 `LIVE = 255` 常量。
  **移植时保留这个常量，不要写裸 `1`** —— 早年写成 `1` 的版本进 R8 后被归一化成 0.0039，
  所有阈值把它抹成 0（画面全黑）。
- bake 型在 **Worker** 烘焙 sheet 纹理；sim 型固定步长 + 每 16 步快照 + seek 重放；
  realtime 型逐帧算。**烘焙入参不可打关键帧**（防每帧重烘）。
  - **realtime 型的 fragment 不含头**，由 `ALGO_HEAD`（`algos/shader-lib.ts`）拼在前面；
    def 必须自带 `setUniforms` 把参数派发到 uniform —— **没有它参数永远拿不到值且不报错**，
    只是恒用默认值。`u_resolution` 是**内部**渲染尺寸，`u_aspect` = w/h。
  - **`realtime` 生成器就是「全屏程序化场景」**（angel-echo 的 `scenes.js` 那一型）。
    `AlgoSource.generator` 是自由字符串、realtime 本就渲染整帧，**不需要新的 SourceClip 类型**。
  - 内部渲染高度统一走 `intResParam()`（键 `intRes`，文案 `algo.intRes*` 共用一套），
    别再一个生成器写一份 select。内部低分辨率再放大是性能手段，**不是跳帧缓存**（那破坏确定性）。
  - **尺寸换算只有一处**：`int-res.ts::intResSize(v, renderW, renderH)`。宽高比取自**渲染目标**，
    不许再写 `res * 16 / 9` —— 那会让竖屏工程的 3D 按 16:9 渲染再 letterbox，而参数面板上毫无异常。
    `auto`（= 跟渲染目标一样大，高度封顶 1440）是**只有 3D 用**的缺省值（`sdfParams()` 覆写），
    `intResParam()` 本身的缺省仍是 `480`：那一个键全 realtime 家族共用，把缺省抬上去会让
    二十来个 2D 分形也按全分辨率渲染、并让全部缩略图重烘。
- **bake 型的「揭示」有三种轴**（`types.ts` 的 `BakeReveal` → reveal shader 的 `u_reveal`）：
  `'front-y'`（默认，输出纵坐标，如 Rule 110 逐代向上）/ `'front-x'`（输出横坐标，如分岔图逐列算出来）/
  `'value'`（**像素值本身**，如 L-system 的离根距离场 —— 生长顺序编在值里）。
  三者共用 `cell * step(量, u_front)` 的形状，所以值为 0 的背景在任何模式下都不会被点亮。
  `BakeResult.frontMax` 的口径随轴变（行数 / 列数 / 255）。守卫：`tests/unit/algo-uniforms.test.ts`
  断言三种模式都至少被一个生成器用到。
  - ⚠️ **`'value'` 用来编「揭示顺序」时，那个量必须真的随揭示单调**。挑错了不会报错，
    只会让动画在第一帧演完。两条实测踩过的选错法（现在写在各自文件头）：
    **按命中密度**（混沌游戏 —— 它的不变测度在吸引子上本来就是均匀的，密度只是
    覆盖不全的泊松噪声，归一化后挤在一档）与**按落点序号**（前几千个点就铺满了）。
  - ⚠️ **新增 bake 型生成器要改 `algos/bakers.ts`**，不是 `bake.worker.ts`。
    那张表原来是硬编码在 worker 文件里的，而 worker 挂了 `self.onmessage` ⇒
    Node 里 import 就炸 ⇒ **没有任何测试读得到它 ⇒ 漏登记不报错**：`BakeClient`
    只在控制台打一行，画面永远空帧。实测代价是「批量导出缩略图 25 张成功、
    2 张纯黑，而整套单测全绿」。现在表在 `bakers.ts`，由 `tests/unit/bake-registry.test.ts` 钉住。
- **程序化场景 = `realtime` 生成器，共用 `SCENE_GLSL`**（`shader-lib.ts`）。
  它 = 已登记的 `FBM6_GLSL` + `MATH_GLSL`（就是 angel-echo 的 `LIB`，**不要抄第二份**）
  + 音频特征 uniform 块 + `edge()`。所以场景体里写 **`fbm6(...)`**，不是上游的 `fbm(...)`。
  场景 id 一律带 **`scene-`** 前缀 —— 特效注册表里已有 `tunnel`，另有 `kino-datamosh` /
  `audio-bars` / `flow-contours` 这些近似名；两张表技术上不冲突，但试炼场左栏（源）与
  右栏（特效）同时出现两个「隧道」是纯粹的误导。
  - `setUniforms` 一律用共用的 `sceneUniforms(extra)`；编排量（密度 / 扭曲 / 色调 / 切段 / 升调 / 进度）
    是 `arrangementParam()` 造的**普通 range 参数**，用户自己打关键帧 ——
    **不要**把 angel-echo 的 `plan.js` 段落表搬进来（根 `AGENTS.md` 的参考代码地图明确「不要拿」）。
    `extra` 是**该场景私有的 range 参数键**（如 `scene-ripple` 的 spacing / drive / sharp…）。
    ⚠️ **`realtime` 生成器的 select 参数派发不了**：`floats()` 里是 `Number(v[key]) || 0`，
    字符串值会静默变成 0。realtime 要区分形态就用 **0..1 的 range**，不要用 select。
  - **`scene-pulse` / `scene-tunnel` / `scene-dissolve` 已合并成 `scene-ripple`**（2026-10）。
    三条的主项都是 `f(r)` 的环，肉眼几乎不可分；合并后环距 / 驱动 / 锐度 / 辐条 / 噪点
    全是参数。别再去找那三个 id。

- **生成器也有接线自检**：`tests/unit/algo-uniforms.test.ts`（与 `tests/unit/effect-uniforms.test.ts`
  共用 `tests/unit/_uniform-probe.ts` 的伪 GL 骨架）。判据：realtime 的 fragment **没有重复声明 head**
  / **声明的都被写** / **写入类型与声明一致** / **没摸到未声明的名字**。
  这一类失效全是静默的（拼错名字、`uniform1f` 写 `int`），`compileAll` 看不见。
- 烘焙是**异步就绪**的：未就绪时该层返回 `null`（「这一层缺席」）。试炼场工具栏把
  「源：等待中 / 就绪」显式化。
- openmosh 的 Rnd 按钮用裸 `Math.random()`；移植时换成 `mulberry32(hashSeed(...))`，
  于是「第 1 次点随机」在任何机器上都是同一组参数。
- 视频 / 音频这类**异步就绪**的东西，性能只能从**导出路径**量。预览缺帧时用最近的帧顶上
  （很快），所以「连着渲 N 帧再计时」量到的是渲染缓存纹理的成本 —— 会得到荒谬数字。
  `ExportOptions.onFrame`（`export-runner.ts`）给出每帧真实耗时，`__artmatic.exportTiming(n)`
  是它的 E2E 出口。

### recall（闪回，`flashback.ts`，2026-10）

唯一**依赖工程内容**的生成器：它不算像素，而是让宿主把工程在**过去某个时刻**
整帧重渲一遍，当作这一层的源（`render/recall.ts`）。三条硬约定：

- **回放窗口夹在片段头之前**（`recallWindowOf`），且取的永远是「片段头之前的
  最后一帧」。这不只是「倒放之前的画面」的语义 —— 它同时保证**递归良基**：
  `gap=0` 时窗口末端正好是片段头，不挪开一帧，回放帧里就会包含闪回片段自己。
- **没有 `intRes`、参数不能打关键帧、没有 fragment**：多一道 pass 只会把回放帧
  重采样一次；而窗口是可打关键帧的量产不出确定的速度（速度由片段几何推出）。
- **每帧多一次整帧渲染**（≈2× 成本），这是这个功能的固有价格，不是可以优化掉的
  实现细节。已知近似（都是「顺序播放的产物、随机回跳没有定义」）：回放帧里
  **反馈类特效的历史每次清空**、**斑点追踪为 null**；视频由导出预热解到精确帧
  （`RecallService.prepare`，只做第一层）。

工厂默认值 `back=0 / gap=0` = 「片段之前的全部」，0 是哨兵（0 秒窗口本身
无意义，拿它当哨兵不会与真实用法冲突，而出厂默认只能是静态数字）。
守卫：`tests/unit/flashback.test.ts`（窗口与时间映射）、
`tests/e2e/algo-flashback.spec.ts`（**回放帧 == 垫底素材在过去那个 t 上的帧**，
含方向断言）。

### 基础图案（`bars` / `grid` / `gradient`，2026-10）

三条从 `lab/patterns.ts` 的测试图**产品化**而来，但**不是同一份实现**：lab 那三张
仍是「审特效」专用的 `lab:` 伪 id（见 `lab/AGENTS.md`），这三条是用户可选的生成器。

- **与内部分辨率解耦**：`intRes` 是纯性能档位，画面不该跟着它变。所以 `grid` 用
  **纵向格数**（`u_cells` + `u_aspect`）而不是「32 设备像素一格」—— 后者正是 lab
  版的口径（那里要的就是设备像素级的问题）。新增图案类生成器时先问「缩略图/预览
  与导出的格距会不会随 `intRes` 漂」。
- **`half` 是 GLSL ES 的保留字**，`float half = ...` 直接编译失败（实测）。
  同类的还有 `input` / `output` / `filter` / **`flat`**（插值限定符 —— 想给「平面坐标」
  起名时手最容易伸向它，`noise-field` 实测踩过）—— 变量名别用这些词。
- 彩条用 HSV 等分色相而不是硬编码 7 色：条数是参数，硬编码表跟不了。
  渐变的三形态用 `int` uniform 分派（`selectInt`），不要用字符串 uniform。

### 噪声库（`noise-lib.ts`）与噪声场（`noise-field.ts`，2026-11）

**新代码要 2D / 3D 噪声就 import 它，不要再往生成器里贴一份私有实现。** 三族
（value / gradient / voronoi）× 两个维度，每个都有 `nz` 前缀（`nzValue2` / `nzGrad3` /
`nzVoronoi2` / `nzFbm2` / `nzWarp3` …）。前缀不是洁癖：`FBM6_GLSL` 里已经有
`vnoise2` / `fbm6`，同名函数在同一个 fragment 里是 **redefinition 直接编译失败**。

- ⚠️ **`NOISE_GLSL` 自带 `HASH_FAST_GLSL`。** 同一份 fragment 里再拼
  `FBM6_GLSL` / `HASH_FAST_GLSL` 就是 `function already has a body`，而着色器是
  惰性编译的（点到它之前一声不响）。真要并存就用 `NOISE_BODY_GLSL`（只有函数体）。
  守卫：`tests/unit/noise-lib.test.ts` 的「每个 realtime 生成器最多定义一次 hash21」。
- **噪声基元保持 0..1 且不逐阶截平。** gradient 的缩放取 0.9 而不是 1.5：
  实测 ×1.5 时每一阶都往两端夹一次，fbm 平均出来是一块块**平台**，画面接近二值图，
  而且加「细节层次」也救不回来（平台是逐阶产生的）。要硬要软只在生成器的
  `contrast` 一处截 —— 那一处是最后一道，改坏了看得出来。
- **fbm 必须归一化**（`sum / norm`）：不归一的话「阶数」会顺手改掉整体亮度。
  `nzCentered` 只给「当位移 / 权重」用（归一化 fbm 的标准差只有 0.1，直接当位移
  等于没有位移）；当密度 / 阈值切的地方直接用 fbm 原值。
- **`smoke` 的 3D 噪声已并进来**（`smokeFbm` = `nzFbm3(..., 0.5, 2.03)`，逐位等价于
  旧的 `fbmS`）。它那两个实测分位数（p99.9 = 0.81、包络 p90 = 0.41）是**按这套归一化
  量的** —— 改 `nzFbm3` 的归一化或阶数要重测那一组，否则烟雾会静默变空 / 变灰墙。
- **`noise-field` 两种模式都在三维里采样**，差别只在流速怎么用：二维是流速在平面上吹
  （深度冻结在 `u_evolve`），三维是流速往深度里穿。不做等轴测 / 三平面投影 —— 这条
  生成器的身份是「场本身」（灰度、可直接当 mask 源的 luma），投影会把地形感混进来。
  **别为了省那点毫秒把二维退回 `nzFbm2`**：演化只能靠额外的维度，退回去它就成了第二个
  流速；而且 `u_evolve` 一动整幅会换一套噪点（同样的参数突然不是同一张图）。
  E2E 钉了「t=0 且流速为 0 时 2D / 3D 逐点相同」（`tests/e2e/algo-noise.spec.ts`）。
- **`u_evolve` 是进度不是速度**（单位：格）。做成进度是为了能打关键帧 / 挂调制器；
  「恒速换形」那种语义已经由 `speed` 表达（三维模式下它就是持续换形）。`speed` 的单位
  是**格/秒**（乘了 `u_scale`），所以 `speed = 0` 时画面对 `t` 逐点无感。
- 频率一律走 `u_scale`（画面高 = scale 个噪声格），**不按设备像素算**：`intRes` 是
  性能档位，改它不该改图案。三个 `select`（族 / 维数 / voronoi 形态）走 `selectInt`，
  `octaves` / `invert` 走 `ints` —— 过 `floats()` 会静默变成 0。
- 成本（480p、默认参数、10 帧取 5 轮最小值、含一次读回摊薄）：value ≈1.2 ·
  gradient ≈1.3 · voronoi ≈1.8 ms，**二维与三维同价**（只差流速加到哪个坐标）。
  要盯的是**族与阶数**（voronoi 三维是 27 格 × 3 hash/阶），不是像素数。
  单次读数会抖 ±0.4 ms，别拿两次不同时间的数字比大小。
- **域扭曲只做平面（`nzWarp2`）**，两种模式都一样：三维扭曲要采样三次而不是两次，
  而它只是「把空间揉一下」；何况统一之后 t=0 的二维与三维是同一张图，
  心智模型就是「一个场，两种走法」。

### 正多面体（`polyhedron.ts` + `polyhedra.ts`，2026-10）

**线框不走 `sdf-lib`**：棱是零厚度集合，距离场在棱外处处返回「最近的面」而不是
「最近的棱」，步进会直接跨过去（细线断成一串点）。这里做的是**逐棱的屏幕空间
线段距离** —— 每像素一圈棱（最多 96 条，`MAX_SHAPE_EDGES` 是循环的编译期上界），
换来精确的抗锯齿、精确的深度、任意细的线。

- **三维与四维是同一条路径**：顶点存 `vec4`，三维形体的 `w` 恒为 0 ⇒ `project4`
  对它是恒等；旋转平面由 `rotPlanes(dim, axis)` 从「该轴不动、在它后面两个坐标
  构成的平面里转」这一条规则推出（三维模 3、四维模 4）。别为四维另开一个分支。
- **形体表在 `polyhedra.ts`，只写坐标**：棱由「最短顶点对距离」连出来（正多面体
  的定义本身就是判据），顶点一律外接半径 1。加一个形体 = 那个数组加一行，
  两张平坦常量表与 `SHAPE_RANGE` 自动跟着长。守卫 `tests/unit/polyhedra.test.ts`
  钉住每个形体的顶点 / 棱数（错一个符号就会变）与区间首尾相接。
- **`dim` / `solid` / `cell` / `axis3` / `axis4` 都是 select**，派发必须走显式映射
  （`SHAPE_RANGE` / `rotPlanes`）—— 过 `floats()` 会静默变成 0，也就是永远渲第一个形体。
- 四维的「绕某轴旋转」在这里定义成「该轴不动」：x→YZ、y→ZW、z→WX、w→XY。
  只有 y / z 是 w 参与的平面，也就是只有它们会给出超立体的「呼吸」。

### 机器可读符号（`qr-code.ts` + `symbology/`，2026-10）

一个生成器把文本编成七种符号之一：QR Code / Code 128 / Aztec / Data Matrix /
MaxiCode / Grid Matrix / 汉信码。

**保真度是两档，别混着说**：

| 档 | 符号 | 判据 |
|---|---|---|
| 完整标准（**扫得出来**） | `qr` / `code128` | 与 MIT 参考实现逐位对拍（`tests/unit/symbology.test.ts` 的金标） |
| 结构复刻（**不保证可扫**） | 其余五种 | 定位图形 / 尺寸增长 / 真实 RS 纠错都在，精确的码字布局没做 |

- **界面文案不许承诺「可扫」**。`structural.ts` 文件头写了为什么不做那五种：
  它们是真·表数据 + 分支特例，没有可信参考实现就只能是猜，而猜错恰恰是
  「看着完全正确、扫不出来」—— 这条比「少五种」贵得多。
- **借 `sim` 通路，但它没有步进状态**：`create()` 里编码一次、`seek()` 是 no-op、
  `current()` 交同一份字节。三个硬需求筛掉了另外两种型 —— CPU 编码（GLSL 做不了）、
  **不能有揭示动画**（bake 的 front 由 `t` 驱动，片段头那一帧前沿为 0 ⇒ 整幅不显示）、
  每帧要有一张按参数烘好的纹理（realtime 的 `auxTextures` 只按 kind 全局缓存，不看参数）。
  `seek(f) ≡ 顺序 step f 次` 因此**平凡成立**。
- **纠错级有两套编号，混用是静默的**：表行序是 L/M/Q/H = 0/1/2/3，而格式信息那几位是
  L=1 / M=0 / Q=3 / H=2（`EC_FORMAT_BITS`）。首版混用，结果 16 个格子全错
  （15 位格式信息 + 固定黑模块）但图看着完全正常。
- **GF 的尺寸必须与码字宽度匹配**：拿 GF(64) 算 8 位字节会读到 `log[200]`（越界 →
  `undefined`）→ 乘法 NaN → 异或当 0 ⇒ 纠错码字整段归零。实测形态是「数据区尾巴
  整行全白」。8 位码字一律 GF(256)，4 位（Aztec 的 mode message）才用 GF(16)。
- **AA 不能逐格算 SDF**：两个相邻暗模块的公共边上距离恰好为 0，会被画成一条 50% 的
  缝 —— 整张码浮出一层细网格线，定位图形的实心区域里也全是线。默认模式按
  「邻格是白才算轮廓」判（并集），`round ≥ 0.02` 才逐格画圆角（那时缝是目的）。
  另外 `smoothstep` 的带宽取 `fwidth(q)`（模块空间像素尺寸），不要取距离场的导数 ——
  距离场在分支里取值，非一致控制流下导数不可靠。
- `qr-tables.ts` 是**生成物**：两张表由一次性脚本从上游 `qrcode.js` 提取
  （脚本思路：找到 `VAR = [ ... ]` 字面量、去注释、`JSON.parse`）。手改一位不会有
  任何报错，只会让码扫不出来 —— 金标会红，但别让金标先红再改表。
- 金标怎么重放：把 `qrcode-generator` 的 `qrcode.js` 存成 `.cjs`（工程是
  `type: module`），`qrcode.stringToBytes = qrcode.stringToBytesFuncs['UTF-8']`，
  再对每组 `(text, ec)` 取 `isDark(row, col)` 拼成 `0/1` 行、`sha256` 前 32 位。
  **金标必须来自参考实现**，自己算自己当金标等于没测。
- 缩略图：`node scripts/gen-algo-thumbs.mjs --only=qr-code`。
- 新增一种符号 = `symbology/index.ts` 的 `SYMBOLOGIES` + `STANDARD` + 选择器文案
  （`algo.qr.sym*`）；结构复刻放 `structural.ts`，能对拍放自己一个文件。

### 流线（`streamlines.ts`，2026-10）

`realtime` 型，**没有任何逐帧状态**：整条线是 `u_time` 的闭式函数（错相 +
从发射点生长到接受点）。只有踩过才知道的几条：

- **多点参数只能一个点一个 `vec3`。** `ParamDef` 没有数组这一档，而
  `uniform vec2 u_x[4];` 既过不了 `declaredUniforms` 的正则（`u_\w+;`），
  也不在伪 GL 的写入类型表里 —— 等于接不上那两条守卫。取点走 `emitPoint(int)`
  的 if 链：**GLSL ES 3.00 里不要对向量/数组做动态下标**。
- **渐变长度是世界距离，不是笔画的百分比。** 按百分比算时每条笔画只剩中间
  一小段亮着（笔画越短越像虚线），整屏都是断的、而且不像 bug。线宽反过来要按
  **路径位置**给，否则各条线的粗细过渡落在不同位置。
- **距离用折线的真实距离，扭曲只是叠上去的有符号横向位移。** 这条换了三种
  写法才稳：① 把摆动折进逐段采样，高频摆动画成一串折线（28 段也不够）；
  ② 只用最近点的法向投影 `|sd − wob|`，远处像素被当成「沿切线无限延长」点亮
  （发射点后面长出悬空的线头），亚像素细线还会被打成串；
  ③ 现在这个 `|bestAbs·side − wob|`：`bestAbs` 保证远处不亮、两端自带帽。
  另外摆动比路径还陡（`|wob′| > 1`）时等距曲线会自交、距离场失去定义，所以
  `freq ≤ (0.75·L/amp − 4) / 2π` —— 幅度越大，能给的波数越少。
- **一段线是「软管里的一滴墨」，不是「从头长到某长度后停住」。** 可见区间
  `[尾巴, 头]` 由同一个行程函数给出（尾 = 头 − 线段长度）：先在发射点挤出来，
  尾巴脱离后整段等长往前滑，头到接受点后尾巴追上来、整段被吸收。写成「停在
  原地」的话线段永远到不了接受点 —— 这正是第一版做错的地方。
  `segLen = 0`（出厂）时尾巴永远贴着发射点，`周期 = life`，与没有这三个参数
  时逐像素相同；有限长度时 `周期 = min(尾巴走完的时间, life) + 等待`。
  线宽 / 两端渐变 / 虚线花纹都按**这一滴墨自己的坐标**（从尾巴量起）算，钉在
  路径上会让花纹从墨滴身上流过去；渐变长度还要按线段长度收口
  （`min(fade, 0.45·segTotal)`），否则一段 0.05 长的线段整段都在渐变里，
  实测整帧 lit = 0。
- **点位默认值两两不能重合**（发射点 × 接受点）：重合 ⇒ 贝塞尔退化成一点 ⇒
  整束缩成发射点上的一个小团，全程不报错。守卫 `tests/unit/streamlines.test.ts`。

成本：`密度 × 28 段`/像素（上限 32 条），每线一次包围圆剔除；1280×720 默认
参数实测约 5 ms/帧（含一次读回）。

### 跃动几何（`kinetic-shapes.ts`，2026-11）

MG 背景型：满屏几何形各按自己的相位出现/消失，进出场方式可选。`realtime`，
**全闭式**（`fract(t·rate + 相位)`），没有逐帧状态；`rate = 0` 时画面对 `t`
逐点无感（E2E 钉住）。

- **包围圆剔除的半径必须 ≥ 形状的外接半径，不是「尺寸」。** 方形的角在
  **r√2**、iq 的等边三角形（那个式子的 `r` 是半宽）三个角在 **1.155r**。
  按 r 剔除的后果不是「角有点毛」——`方形 ∩ 圆(r)` 恰好是**内接圆**，
  于是「方」直接画成一个圆，而且**完全不报错**（实测踩过，缩略图才看出来）。
  现在剔除用 `1.5r`，三角形的半径按 `0.866r` 收口（让五个形状同一个外接口径）。
- **进出场方式在 JS 里译成 `vec3`**，shader 只读三个通道的开关
  （缩放档 / 滑动 / 淡入淡出）。理由有两条：`realtime` 的 `select` 过
  `floats()` 会静默变成 0；而十个档位本质上是三个通道的组合，写成十个
  shader 分支既没必要也没法组合出「滑动＋淡入＋放大」。
  ⚠️ 加一个选项就必须在 `ANIM_TABLE` 加一条 —— 缺了会**回落到硬切**
  （选项还在、拖了没反应）。`tests/unit/kinetic-shapes.test.ts` 守着。
- **缩放要作用在距离场上**（`sdShape(q/sc) * sc`），不是把 `rad` 乘一下：
  后者改的是形状的**尺寸参数**，圆看不出来，方/三角会跟着变形。
- 布局派生量（`u_count` / `u_cols` / `u_rows` / `u_cell`）由纯函数
  `layoutOf()` 算，输入只有「密度 × 宽高比」——于是 `intRes` 只改分辨率、
  不改构图（与 `grid` / `noise-field` 同一条纪律）。

### 网格尺寸：`width` / `height`（2026-10）

网格类模拟的尺寸是**两栏**（列 × 行），参数键固定 `width` / `height`，单位是格。
协议本来就是这样（`SimHandle.gridW/gridH`、tint 的 `u_srcAspect`、`stampCentered`
都收两轴）；早先每个生成器只写一个 `size` 并内部当正方形用，是移植残留，
16:9 工程里会得到「中间一块方形图 + 两侧底色」。

- 读取一律走 **`gridSizeOf(params, LIMITS)`**（`grid-dims.ts`），别再写
  `Math.round(Number(params.size) || n)`。`LIMITS` 的 min/max/default 必须与参数表
  同源；UI / Agent 反推尺寸走 `gridSizeFromDefs(params, def.params)`。
- `gridSizeOf` 保留 `size` 兜底（单轴缺失时两轴都取它）：老工程由
  `core/schema.ts` 的 **v15 → v16** 迁移拆成两栏，兜底只服务手改过的文件与老式单测。
- **环面回绕必须按两轴分别取**（`x` 用 `w`、`y` 用 `h`）。把 `w` 当高用不会报错，
  只会读到错行 —— 单测里要用「宽高不等」的网格才抓得到。
- `TorusField` 支持矩形：`new TorusField(w, h, kernel)`（旧的 `(n, kernel)` 仍成立）。
  上下 halo 复制**整行**（连左右 halo 一起），四个角才不会错。
- **仍保持 `size` 的方形**（不是没做，是模型本身）：雪花（六角格半径）、佛像
  （复平面方窗）、`dla` / `chaos-game`（bake 的输出方形）。

### 参数类型：`bitmask` 与 `pattern`（2026-10-04）

两个新变体是为「规则可调 / 种子可画」加的，它们**都不需要抬 `SCHEMA_VERSION`**
（运行期逐键 `?? defaultValue` 合并，见 `runtime.evalParams`）。代价是参数表多了一个键
→ bake/sim 的缓存哈希变了一次 → 老工程第一次打开会重烘一遍。**这是正确行为，不是 bug。**

- **`bitmask`**（`bits` / `groups` / `slider?` / `presets?`）：一个 `0..2^bits-1` 的整数，
  UI 是「可点击的位表 + 数值框」。存在的理由是**同一个控件要服务两种规则**：一维 CA 的
  规则号（8 位）与生命类 CA 的 B/S 掩码（18 位 = 出生 9 + 存活 9）。做成 `range` 的话
  B/S 会得到一条 `0..262143` 的滑杆（毫无语义），而且 `evalParams` 对 `range` 有关键帧
  分支，混进来会让「这参数能不能打关键帧」说不清。
  - 位号 → 行的映射在 **`core/bitmask.ts` 唯一定义**：`'eca'` **高位在前**（111 那一行是
    bit7，`Rule 30 = 00011110₂` 就是这么读的）／`'count'` 低位在前（邻居数 0 起）。
    界面点亮的位与生成器生效的规则必须是同一套映射，各写一份的 bug 形态是
    「点亮的位与画面不符」，看代码看不出来。
  - B/S 的打包：**出生占低 9 位、存活占高 9 位**（`masksFromBS` / `birthFromMask` /
    `surviveFromMask`）。Conway = 6152、HighLife = 6216，**用 `masksFromBS([3],[2,3])`
    算，不要写魔数**。
  - `rule = 0` 是**合法**规则。读值一律 `clampMask(v, bits)`，**绝不要写 `Number(v) || 110`**
    （那会把用户选的 0 换成 110）。

- **`pattern`**（`defaultValue` 是串、`editorSize?`、`mode: '2d'|'1d'`）：一枚
  `WxH:<base64>` 编码串，**空串 = 没有图案**。编解码在 `algos/pattern-codec.ts`，三条纪律：
  1. **永不抛异常。** 它读的是磁盘上的 `project.json`（手改过、旧版本写过、截断过）——
     一律降级成 `null` / 补 0 / 截断，绝不把工程卡在打不开的状态。
  2. **自带尺寸。** 图案不是网格的附属：同一张 32×32 的图案要能盖到 112² 或 256² 上。
  3. **跨环境逐位稳定。** 自带 base64 实现（不用 `btoa`），于是浏览器 / Worker / Node
     三处一致，且能在 vitest 里纯测。
  - **全零图案是合法值**（语义是「清空」），与 `null`（坏串 → 回退随机）是两回事。
  - 盖印一律 `stampCentered`（**居中 + 裁剪**，不缩放）；一维 CA 用 `stampRow`（只取第 0 行）。
    居中而不是左上角对齐：网格远大于手绘图案时，左上角对齐会让图案缩在角落，
    而且改网格尺寸时位置会漂。
  - `seedMode` 语义：`game-of-life` 是 `random | pattern`，`rule110` 是
    `single | random | pattern`。**pattern 模式不消耗 RNG** —— 于是 `seek ≡ 顺序 step`
    这条不变量与旧实现同构，不需要额外的确定性论证。
  - 编辑器（`ui/pattern/PatternEditorModal.svelte`）是**精简版**：涂/擦（经典拖拽语义，
    没有独立笔刷开关）、清空/反相/随机、网格尺寸、几个标准预设。**刻意不做**
    旋转/镜像/平移/洪水填充 —— 它存在的唯一理由是「画出随机撒种给不出的初始条件」。
  - **从素材导入**（`algos/pattern-image.ts`）：把媒体池里的图按**不透明度**采样成位图。
    三条口径：
    1. **采样分辨率 = 模拟网格**（`PatternField` 的 `grid` prop，由
       `gridSizeFromDefs` 算出），于是 `stampCentered` 盖回去是恒等映射；
       超过 `MAX_PATTERN_DIM`（512）时等比缩小，不横向压扁。
    2. **阈值 128，不是 255**。按网格重绘之后每个格子拿到的是覆盖率（抗锯齿），
       要求 alpha 恰好 255 会把 1px 的描边整条丢掉。颜色 / 亮度不参与。
    3. **SVG 走 `<img>` 解码**：`createImageBitmap` 在 Chromium 里不接受 SVG blob
       （`engine/media-assets.ts` 的解码也有同一条兜底）。contain 适配、不拉伸。
    Agent 侧的入口是 `seed_pattern_from_asset`（同时把 `seedMode` 切到 `pattern`，
    一笔撤销）。
  - 画布必须 `data-exempt`、DPR 比较必须 `Math.round`、随机走 `mulberry32(hashSeed(…))`
    （根 `AGENTS.md` 硬约束 1.2 禁止裸 `Math.random()`）。全部改动是**本地草稿**，只有「应用」才回写参数
    → 整个编辑过程是一笔撤销。

### 粒子内核与 `gpu-sim`（`particles/`，2026-11）

第五型生成器。状态在 GPU 状态纹理里，不用 `SimHandle`（纯 CPU 数据 + 8 位量化上传）。
四型之外的分支在 `runtime.ts::resolve`，记账 / 预算 / 对齐与 `sim` 共用 `stepTo`、
`planSimStep`、`advanceBudgeted`、`alignSims`、`takeSimLag`。架构说明见 `docs/particles.md`。

- **内核只从 `index.ts` 进**：`createParticleGenerator(spec)` 是唯一复用 API。
  后续生成器不要复制 `particles.ts`，也不要自己拼 GLSL。`spec.id` 必须唯一。
  `Kit.quad` 按名字缓存 program，名字来自 `particleProgramName(id, part)`。
- **确定性**：一步两个 pass 都读同一份 src，写完才 swap。随机是 `(槽, 步号, 种子)` 的
  闭式 hash（`HASH_FAST_GLSL`，无 sin）。`seek(f) ≡ 顺序 step f 次`，快照存原始字节。
  `Renderer.onSeek()` 的 `alignSims()` 现在也遍历 `gpuSims`，走 `handle.align()`。
  GPU 状态不能靠 `seek(同帧)` 兜，那正是「同一 t 两渲不同」的来源。
- **素材 aux**：`AlgoAuxKind` 多了 `'asset-image'`，`AlgoAuxRef.assetParam` 指向参数键。
  `bindAux(refs, params)` 解析并按「map 里有没有这一项」回退，没有 `On` 开关。
  主 runtime 与 `render/recall.ts` 那台**都要** `setAssetResolver`，漏了回放侧的表现是
  「闪回里贴图丢了」。运行时不缓存素材纹理（`SourceManager` 自己管淘汰）。
- **`compile-all.ts` 编四段 program**；不做 dropped-uniform 判据，状态纹理的 uniform
  不是「参数表 → `u_<key>`」那条链。
- **`volatile` 是分界线**：改 `spriteAsset` / 配色 / 投影不重建模拟；改 `emitAsset` /
  力场 / `count` 会重建并从第 0 帧重放。新加参数时先想清楚它进不进状态。
- **`asset` 型参数只能填 assetId 字符串**，空串 = 未绑定。控制平面在写库前校验存在且
  `kind === 'image'`；打开工程 / 删素材时由 `core/asset-params.ts` 置空。
- **`curve-meta.ts` 与 `Inspector.svelte::keyframable` 都把 `gpu-sim` 与 realtime 同待遇**，
  两处判据必须一起改。

### `SimDef.volatile`：哪些参数**不该**参与「算一次、缓存起来」那段

`bake` 的烘焙入参与 `sim` 的构造参数都会进一个哈希（`runtime.ts` 的 `cacheHash`），
哈希变了就重烘 / 重建。`volatile?: string[]` 里的键被排除在哈希之外。

**为什么需要**：`rate`（速度）、`colorBg`/`colorLive`（配色）、`palette`、`contrast`、
显示开关都**不参与** `create()` / `bake()` —— 它们只在渲染期读。不排除的话，
拉一下配色滑杆就会重建整个模拟。

> ⚠️ 代价说准一点：模拟是**确定性**的，重建之后 `seek(t)` 会从 0 重放到同一个状态 ——
> **画面完全一样**，状态不会丢。重建的真实代价是**时间**：每次重放 `elapsed × rate` 步，
> 长片子上是秒级卡顿。所以这是一个**延迟**问题，不是数据丢失问题。
> （也正因如此，它没有 E2E —— 墙钟断言在 headless 里必然 flaky。机制由
> `tests/unit/reaction-diffusion.test.ts` 的 `cacheHash` 用例钉住。）

**家族约定**：sim 的速度参数一律叫 `rate`，运行时每帧从**当前**参数读它
（`liveRate`）。所以「改速度」连重建都不需要，只是重新映射 `t → step`。

### sim 的状态精度与快照

- **内部用高精度 typed array**（`Float32Array` / `Uint16Array` / `Uint32Array`），
  只有 `current()` 做 8 位量化。**快照必须存内部精度**——存量化后的输出会把每一步的
  舍入误差累积进重放路径，`seek(f) ≡ 顺序 step f 次` 就不成立了。
- 量化的口径逐生成器写在自己的 `current()` 里（如反应扩散把 v 乘 3 拉开窄动态范围、
  沙堆用 `sqrt(h)·96` 让 2 与 3 的差别可见）。**这些是显示处理，不影响状态。**
- **快照用 `sim-util.ts` 的 `SnapshotRing`**，它做**抽稀阶梯**而不是「只留最近 N 张」：
  第 0 帧恒存（任何回退都能从它重放），超过 cap 就把阶梯加倍。
  只留最近 N 张的话，回退到很早的帧就退化成「从第 0 帧重放几万步」。
- **别在回退时丢弃 newer 快照**：`step` 是确定性的，同一帧的旧快照与重算出来的
  状态逐位相同，留着还能省一次重放。

### 元胞自动机家族：默认值必须**实测**选定

7 个 CA / 人工生命生成器（反应扩散、Brian's Brain、循环 CA、沙堆、
雪花、Lenia、Wireworld）的默认值**不是从文献抄来的就完事** —— 有四处是
实测才发现的：

| 生成器 | 文献/直觉的默认 | 实测 | 结论 |
|---|---|---|---|
| 反应扩散 · 撒点密度 | 15%（看着像噪声） | 整场 ×10% / ×60% **8 个预设全空**；×30% 只有 3 个活着 | 改成**只在中间 60% 区域**撒、密度 0.4 |
| 反应扩散 · 预设表 | 8 个 (F,k) | `bubbles` 在标准种子下**任何尺寸任何密度都全空**（需强种子） | **删掉 bubbles**；`spots` 要**小**种子（r=4 才得到稳定斑点，r≥8 崩） |
| 循环 CA | K=12 / θ=2 / Moore（网上常见） | **一步冻死**（8 个邻居落在指定状态的概率只有 1/12） | 改成 **K=8 / θ=2 / Moore**（8.6% 的格子每步在变 = 局域化波前） |
| Lenia | σ=0.015（Orbium 那套） | 在任何 μ 下**一步就死** | 改成 **σ=0.03**（那套窄 σ 配的是 Orbium 自己的环形位图） |

**判据是「画面活不活」**，而它有个陷阱：`ink = 非零格数` 对多态/连续场是**无意义指标**
（循环 CA 的 92% 格子非零、雪花的 100% 格子非零）。要按生成器选判据：
循环 CA 用「相邻两步变了几格」（能抓「冻住」），雪花用「冰的格数」（能抓「不结晶」），
多通道用「某个通道的非零格数」。

### Reiter 雪花：两个**单测抓不到**的 bug（2026-10 修）

第一版文件头写着「长得像不像雪花只能靠眼睛」，而**没有看** —— 于是带着两个 bug 发布：

1. **扩散均值用了原始 `s`，没用 `u` 场**。Reiter 原文把含水量拆成 `s = u + v`，
   **receptive 格（冰 + 冰的紧邻）在扩散场里贡献 0** —— 它们是吸收汇。用原始 `s`
   等于让冰格以 1.0 参与邻居平均 ⇒ 晶体反过来向周围**供水** ⇒ 生长速度与几何无关
   ⇒ **只能长成实心圆盘**（实测 β 0.15→0.55、γ 扫三个量级，全是圆盘）。
   改对之后枝隙里只看到少数非零邻居，界面张力（Mullins–Sekerka）才建立得起来。
2. **六角邻域本身是错的**：偶数列写成 `{(±1,-1),(±1,0),(±1,+1)}`（**本列反而没有邻居**），
   奇数列又是另一套，两套互不对称 ⇒ 邻接关系不满足双向 ⇒ 那根本不是一张六角格。
   后果是长出一个朝左张开的**楔形**。

守卫（都在 `tests/unit/cellular-automata.test.ts`）：邻域的**双向 + 镜像对称**可枚举；u 场规则用
「紧邻吸水 / 次邻被抽干 / 远场不动」三点钉住；再加一条**质心偏移 < 8% 半径**的行为判据。
三条都做过「把 bug 改回去看它真的变红」。

另外两条口径：**边界条件不是装饰** —— 远场钉在 β（`r > 0.92·n/2` 每步重置），
没有它环面会把整个未冻区稀释掉、生长几十步就停摆；**α 的两种写法在 α=1 时重合**
（`u + (α/2)(mean−u)` 与 `(α/2)(u+mean)`），只有前者对任意 α 都是显式欧拉离散化 ——
写成后者时 α<1 会整体按 α 衰减，实测 α=0.4 跑 1600 步只结出 7 个冰格。


**两个生成器被推迟，不是因为难写，是因为实测证明它们不成立**：

- **SmoothLife**：我拿不到一个有把握的转移函数表述，而错的表述只会在「死」与「炸」
  之间二选一 —— 那等于发布一个坏掉的生成器。它同时也是最慢的（ra=20 约 11M MAC/步）。
- **可激发介质（Barkley）**：实现了、也调了 ε×dt 的网格（12 组），但**螺旋与靶形波
  都在 t≈2000 熄掉**，而真正的可激发介质螺旋是**持续**的。要修得先做对的螺旋初始
  位形（半平面加缺口那套不产生持续螺旋）与参数搜索 —— 那是独立的一轮工作。

沙堆还带一条**防卡死的闸门**：`stabilize(..., maxTopple)`。逼近饱和时一粒沙能引发
极大的雪崩（实测能跑几十秒），没有闸门就意味着「撒沙量拉满 + 网格调小」可以直接
卡死主线程。闸门**不影响确定性**（上限是步数的固定函数），代价只是雪崩特别大的
那几步堆暂时没稳。撒沙量另外按 `n²/32` 收了口。

⚠️ **闸门截断是静默的**：被截断时格子里会留下 `h >= 4` 的塔，画面**不再表达模型
状态**，但没有任何报错。判据：`current()` 的映射是 `v = min(255, round(sqrt(h)*96))`，
稳定态 `h <= 3 ⇒ v <= 166`，所以 **`v > 166` 的格子就是没塌完的**。
有一条单测钉着「出厂默认跑满一整条时间轴不许出现这种格子」。

⚠️ **沙堆的成本 ∝ (总沙量)^1.5，与网格大小无关**（中心落点把所有沙倒进同一个格子，
只能靠崩塌把它推向边界）。于是「默认值把网格铺到多满」直接决定能不能算完：

| 配置（24 秒轴） | 总沙量 | 沙/容量 | 整条轴 | 最坏未稳定格 |
|---|---|---|---|---|
| 256² 200/步@30（旧默认） | 144,000 | 73% | 3.39 s | **418** ← 撞闸门 |
| 160² 60/步@60 | 172,800 | 75% | 1.28 s | **192** ← 撞闸门 |
| **160² 60/步@30（新默认）** | 43,200 | 56% | **0.52 s** | 0 |

判据是**绝对沙量**：四万多粒随便跑，十四万粒必截断。

⚠️ **`stabilize` 曾经只塌一次就停手**（崩塌之后不重新入队，只靠「邻居推高它时才
入队」）。它看起来正常纯属巧合：`stepOnce` 的中心落点把同一格重复推进队列
`batch` 次，那些重复条目凑出了够用的弹出次数。**一格 `h=40` 会被弹一次、塌到 36，
然后队列空掉、稳定化就此结束**（实测 `done=1`、`maxH=170`）。有回归守卫。

⚠️ 「阿贝尔性」（顺序不影响稳定态）只在**总沙量 ≤ 容量**（`3 × 格数`）时成立 ——
超过容量时环面上不存在稳定态，稳定化永不终止、只能被闸门截断，而截断点与顺序
有关。那条单测原先用 4000 粒跑 24²（容量 1728），是**靠运气**过的。

### 拖动播放头：步进预算（`AlgoRuntime.setStepBudget` / `planSimStep`）

`SimHandle.seek(f)` 是**精确**语义（`seek(f) ≡ 从 0 顺序 step f 次`，硬约束 1.3），
所以向前跳必须**真的把中间每一步算完** —— 迭代系统没有闭式解，也没有能直接跳到
`t(n)` 的算法。实测一条 24 秒时间轴从头走到尾：**Lenia 1.04 s、沙堆 0.53 s、
反应扩散 0.51 s**，其余 ≤ 0.3 s。整段同步算完 = 主线程冰住几秒（这正是一开始
「向前拖卡、向后拖不卡」的原因：向后被快照环兜住，代价有上界）。

**没有改 `seek` 的语义**，改的是「这一帧渲哪一帧」：拖动期间只推进付得起的步数，
画面显示模拟**真实经过**的某一帧（只是比播放头早），松手后按追赶档继续推进，
追上（`simLag === 0`）就回到精确。三层结构：

| 层 | 在哪 | 职责 |
|---|---|---|
| 令牌桶算术（纯） | `planSimStep` | 决定这一帧想推到哪一帧；余额有上限，不会攒出大跳 |
| 分块执行 + 看表 | `AlgoRuntime.advanceBudgeted` | 单步成本会突变（雪崩），按估算一口气推完会做出几百毫秒的毛刺 |
| 三档策略 | `app-state.syncSimBudget` | 导出/播放 0（精确）、拖动 6 ms、追赶 12 ms |

- **`budgetMs = 0` 是精确路径，且是默认**：导出、播放、lab 静止态、全部单测都走它。
  改动时**不要**在 `budgetMs > 0` 分支里顺手改精确路径那个 `seek`。
- **导出期间预算必须是 0**：导出是逐帧权威输出，渲一张落后于播放头的帧就是错的。
  `syncSimBudget` 因此放在 `tick()` **所有提前返回之前**，lab 那边放在节流 `return`
  之前。
- 拖动时画面会比播放头早 —— 底栏有 `statusbar-simlag` 段做提示（`app.simCatchUp`），
  没有它用户会以为预览坏了。
- lab 的「手势信号」直接是 `setT()`（时间滑杆每次 pointermove 都调它），收回在渲染
  **之后**（要先看到真实滞后）；批量导缩略图因此不受影响。
- 用到的 `performance.now()` 与 `tick()` 里那个降帧率节流同类：**传输层节流，不参与
  内容求值**（硬约束 1.1 管的是内容）。

### 2D 分形：newton / kleinian / lyapunov

三个都是 `realtime`，几何全在 fragment 里。三条只有踩过才知道的：

- **Newton 的 `z ← z − a·f/f'` 必须显式写复数除法。** GLSL 里 `vec2 / vec2` 是
  **逐分量**除法 —— 写成 `a / b` 能编译、能跑、不报错，只是结果完全不是牛顿法。
  实测：正确实现画面平均亮度 **125.2**，换成逐分量除法后塌成均匀色（**12.8**，
  `spread` 直接归零）。守卫两条：`tests/unit/fractals2d.test.ts` 的结构断言（fragment 里
  必须有 `cdiv(...)` 调用点）+ `algos2d.spec` 的 `mean > 80`。
- **`cpow` 走极坐标前必须挡 `r < eps`**：`pow(0, 0)` 与 `pow(0, 负)` 都是 NaN。
- **Kleinian 的常数有适用范围。** 判据出自 Unity Graphics Programming 卷 4 第 2 章
  （Jos Leys 的 2-cycle 逃逸时间法），其中 Line3 的分界公式里 `1.95 / 7.2 / 15`
  是按 `u ≈ 1.94` 标定的 —— 所以 `real` 的参数区间刻意只给 1.80..2.10，
  放开就会从「圆链」退化成一片条纹。**这次的 DE/判据是照权威来源逐字写的，
  不是凭记忆**（`apollonian` 那条 DE 就是凭记忆写错的）。
- **Lyapunov 的序列用 `pattern`（1D）而不是 `bitmask`**：序列的身份由「位模式
  **和** 长度」共同决定（`AB` 与 `ABB` 编成同一个整数），而 `pattern` 自带宽度。
  shader 侧用 `floor(bits / exp2(k)) mod 2` 取位（GLSL ES 3.00 没有整数位运算），
  所以 **24 位是硬上限**（float32 的精确整数界，单测钉着它）。三条回退规则都
  回退到 `AB`：解不出 / 长度 < 2 / **一位都没点亮**（全是 B 会让 a 区间完全
  失去作用 —— 用户拖 a 的上下限却什么都不动）。

**这一批最贵的教训是「判据本身也会骗人」**，两条都实测过：

1. **把颜色压成一个标量之后，有些调色板会变成常量。** 余弦调色板的三个通道
   恒差 2π/3 ⇒ `(R+G+B)/3` 对**任何** t 都是 127.5。Lyapunov 换序列明明换了图，
   用亮度比出来的 L1 只有 **0.086**（正好是那条读回竞态的量级），判据完全失效。
   现在 `_stage.gridStats` 的 `samples` 存**逐点 RGB 三通道**，`sampleL1` 逐通道比；
   「有没有结构」用 `spread`（单通道最大跨度），**不用 `mean`**。
2. **分块均值对「铺满整幅的彩色渐变」同样不敏感**（3D 那边是「黑底 + 一块亮
   形体」，分块均值在那里才有效）。要按图的统计特性选判据。

### 3D 内核（`algos/sdf-lib.ts`）

四个 3D 物体（`menger` / `mandelbulb` / `apollonian`，以及 2026-11 加的场景
`scene-3d`）共用**相机 + 步进 + 法线 + 光照 + 雾**；几何在 `sdf-geoms.ts`，
生成器只写自己的运镜与参数表（见下面「3D 场景」一节）。

- **`sdfKernel(sd)` 是模板函数，不是 `#define`。** GLSL 没法把函数当参数传，
  所以共享的步进循环必然要知道调哪个 SDF。`#define ART_SD(p) sdX(p)` 那条路
  还得配一句**前向声明**（使用点在定义之前），两处要同步；模板只有一个真源。
  ⚠️ 但模板也**必须自带前向声明** `float sdX(vec3 p);` —— 忘了就是
  `no matching overloaded function`，而报错行指向内核里那句调用，像内核写错了。
- **uniform 分两批派发，不许合并**：基础 14 个（`u_steps/u_maxDist/u_stepScale/
  u_eps/u_fov/u_light/u_gain/u_fog/u_ao/u_palette/u_color/u_colorB/u_bg/u_bgMode`）
  走 `sdfUniforms()`；着色 9 个（`u_shadow/u_shadowSteps/u_gloss/u_ambient/
  u_pointPos/u_pointPow/u_pointCol/u_fogCol/u_tonemap`）走 `sdfShadeUniforms()`。
  **`tunnel3d` 也调 `sdfUniforms()`，但它不声明着色那批** —— 把着色塞进基础批就是
  「摸到未声明的 uniform」，`algo-uniforms.test.ts` 直接红。参数侧同构：
  `sdfLightParams()` 两边共用，`sdfShadeParams()` 只进 `sdfParams()`（三个分形）。
- **`menger` 的 `steps/fog` 默认值刻意不同**（保住上游那张画面），**但文案键必须同源**。
  `ao` 是反向破例（0 → 0.55）：新着色把「距离衰减压全部明暗」那条腿拆掉了，
  AO 归零会让深洞塌成一片平灰。**上游那张参考画面已不可能逐像素复现**。
- **`u_stepScale` 不是「越接近 1 越好」**：分形 DE 多是**过估**，按 1.0 走会
  在结构内部直接穿过去，表现为整块噪点。Menger 0.9 够用，其他分形按需压。
- **光方向用两个角度**（`lightAz`/`lightEl`）而不是 vec3 —— `ParamDef` 没有
  vec3 这一档。默认 (-45°, 44°) 复现 `menger` 上游那个固定光向。点光位置复用同一
  对角度加一个 `pointDist`（不另开 `pointAz/pointEl`）。
- **`sdfNormal` 的 eps 必须走 `sdfNormalEps(dist)`**（= 命中容差的 2 倍）。硬编码
  常数的两种坏法：低于容差 ⇒ 差分点落在判据带内、法线逐像素翻向（高光闪烁）；
  远大于容差 ⇒ 抹掉细节。`tunnel3d` 是例外（`sdfNormalMat(q, 0.0022)`），
  它的 eps 是按壁面刻符 6e-3 宽调的，换成自适应会把刻符抹平。
- **软阴影没有随机源**：不许用 `gl_FragCoord` 抖动、不许用帧号。抖动换平滑是
  常规做法，而这里的判据是「同一个 t 两渲逐像素相同」（`algos3d.spec` 的 L1 < 1）。
- **软阴影的步长上界按 `maxt` 的比例夹**（`maxt * 0.1`），**不能按 `mint` 的比例**。
  `mint` 是容差的 2 倍、近景只有几毫，乘 8 之后 12 步总共走不到一个单位 ——
  射线还没到遮挡物就烧完步数，表现是「开了阴影画面几乎不变」而且不报错。
- **`tonemap` 默认是 `none`，不是 ACES**：ACES 会连暗部一起抬（`ACES(0.1) ≈ 0.13`），
  默认开着就是一层灰雾，分形的褶皱全糊平。它是「压高光」的可选档，不是画质档。
- **`menger` 保留自己的相机**（同时转 `ro` 与 `rd`，上游写法）：与 `sdfOrbitCam`
  数值等价但参数化不同，换过去取景就变了 —— 它是唯一有上游参考画面的对象。
- **「无限延伸」= 折叠坐标，不是另一种几何**。把 `p` 折回 `[-1,1]³`
  （`mod(p + 1, 2) - 1`）就是同一套八度图案铺满空间 —— 图案本来就以 2 为周期。
  ⚠️ 折叠之后**必须去掉外框约束** `max(|p|) - 1`：它在折叠坐标里恒 ≤ 0，看着无害，
  但在 `|p| = 1` 那一圈恰好是 0 ⇒ 整张 cell 边界都满足 `d < eps` ⇒ 步进在任意位置
  立刻判成命中（画面变纯色）；镜头正落在边界上时命中距离为 0。所以无限分支把
  `d` 的初值设成 `-1e6`。两条症状都不报错，只表现为「某些时刻整帧全黑」。
- **命中判定是 `hit < 0.0`，不是 `hit <= 0.0`**：`sdfMarch` 的未命中哨兵是 -1，
  而 0 是合法命中（镜头贴住表面）。写成 `<=` 会让贴墙的那几帧退回底色。
- **穿梭镜头 = 沿轴直飞 + 段尾换轴**（`SDF_FLY_GLSL`），不是一条连续曲线。
  正弦漫游在周期结构里就是没头苍蝇：它不知道走廊在哪。可行空间本来就是沿轴的
  —— Menger 的八度 1 十字孔是三条互相垂直的贯通隧道（走廊中心 `p ≡ 0 (mod 2)`、
  半宽 1/3，深层八度只会加材料），Apollonian 的距离场以 2 为周期。
- **每段飞正好一个周期（2 个单位）**，于是段末与段首**模格同余** ⇒ 下一段直接从
  段首重新开始，画面连续、路径 O(1)、天然确定。前提是 `head` 对六个方向都落在
  可行空间里（Menger 取原点，那是三条隧道的交点）。
- **换轴不许折返**：轴按 `(base + step*n) % 3` 循环，相邻两段必然换轴，绝不会退回。
  ⚠️ 别用「查上一段方向再排除」的写法 —— 上一段自己也依赖再上一段，拿
  `hash(n-1)` 的原始值去比会漏，漏的那一段在边界上硬切 90°（实测 400 段漏 1 段）。
  代价是不会出现「直着继续飞」的段，这是换取闭式可达的取舍。
- **转弯窗口跨过段边界**（前一段 70% → 下一段 10%），相位走 smootherstep，
  **插值必须用 slerp 不能用 `normalize(mix())`**：弦插值的中段角速度是两端的 2 倍，
  看起来「转起来突然加速再突然停」。
- `sdfCameraClear`（沿梯度推出实体）是兜底，不是主要手段。梯度用 6 点差分而不是
  四面体：四面体在退化点会 normalize 零向量得到 NaN，相机坐标一 NaN 画面整个消失。
- **上向量必须显式给**（`sdfCamWithUp`）。`sdfCam` 把上向量钉死成世界 +Y，
  视线一竖直 `cross(+Y, f)` 的长度就趋 0，右向量的方向由浮点噪声决定 ——
  表现是「镜头看天花板时猛地转 180°」。环绕相机不会竖直看，所以一直没暴露。
  `sdfFlyUp` 用两条投影加权：`(1,1,1)` 方向当参考的那条**永不退化**（离所有
  飞行方向至少 35°），世界 +Y 那条负责把地平线摆正；权重 `1-|fwd.y|`。
  换参考的那段是连续滚转，不是突跳。
- **apollonian 只在 XZ 平面里飞**（`sdfFlyCam` 的 `axes = 2`）。球堆沿竖直方向
  同样以 2 为周期，但头上脚下是一整片纯色 —— 竖直段的整屏没有任何结构。
  这是几何决定的，不是相机的事。
- `flyTilt` 是绕视线的固定滚转角（°），可打关键帧做荷兰角；`flyShake` 是高频抖动。
  两者都在算出 fwd / up 之后作用，不影响正交性。
- 成本实测（headless，720p / 70 步 / 5 级递归）：比纯色只贵 **约 3 ms/帧**，
  读出同步才是大头。加软阴影（12 步预算、提前返回后平均 6~8 步）+ 点光阴影
  （减半预算）实测量级是 ×1.25，最坏配置（24 步 + 点光全开）约 ×1.9。
  要盯的是 `iter`/`depth`/`shadowSteps`（每步的 SDF 成本）而不是像素数。

### 材质型内核（`sdfKernelMaterial`）与走廊场景（`tunnel3d.ts`）

`tunnel-3d` 用第二个内核：SDF 返回 `vec3(距离, 材质号, 自发光场)`，步进回传材质与
**沿射线积分的辉光**。理由是「走廊」不是一个物体 —— 壁、拱架、灯带、窗外方碑要用
不同的材质与自发光规则着色，而 `sdfKernel` 只能回传距离。相机 / 射线那一段两个内核
共用 `SDF_CAM_GLSL`，别各写一份。

走廊类 SDF 有四个**只在这类几何上出现**的静默失效，都会表现为「画面碎成一块块」：

- **盒距离不能用 `max(abs(a)-A, abs(b)-B)`**。那是盒 SDF 的**内部**形式，外部在角上
  高估到 1.41 倍，步进直接跨过薄构件（拱架被切成一段段方块）。用 `box2`/`sdBox`
  那条 `length(max(q,0)) + min(max(q),0)`。
- **按 cell 序号的哈希会让几何在边界上跳变**。同一个边界在两侧属于不同 cell、算出
  不同半径 ⇒ 距离场不满足 Lipschitz（实测 8.1）⇒ 步进跨构件。装饰要挂在**边界**上
  并按**边界序号**取哈希，`zb` 才连续。只减材料的开口（窗口）可以按 cell 取哈希：
  算不出邻居的洞只会让距离偏小，是保守的。
  「管壁分段」（`wall = rift`，每 N 节空 M 节）走的就是这条豁免：它整节去掉壁，
  所以按 cell 序号取模是安全的；**只要它开始加东西（不是减），就必须改回边界序号**。
- **角度方向的频率必须是整数倍的 2π**。`sin(ang * 2.5)` 在 `atan` 的 ±π 分支切割
  处乘的是 5π（半周期）⇒ 符号翻转 ⇒ 半径跳 0.09 ⇒ 距离场沿一条射线断裂。实测这一项
  单独把 Lipschitz 从 1.16 抬到 8.8。
- **极坐标写的截面（`length - R(θ)`）只是径向距离**，角向的 dR/dθ 会让距离场高估。
  `g_lip = 1/sqrt(1 + (R′/r)² + (R′·twist)²)` 在 `main` 里按当前截面取一次最坏值
  （16 个 `secR` 采样，成本可忽略），整幅按它缩步长。

### 外景（`sdScenery`）：世界坐标与「尺度」

隧道之外的东西（城市 / 管网 / 巨构）全部按**世界坐标**求值，它们才会真的从镜头旁边
滑过去。四条只有真做过外景才知道的：

- **`pathAt(z)` 返回的是 (x, **y**)，不是 (x, z)。** 中心线的横向摆动在世界 x 与 y 上，
  轴线是 +z。拿它的 `.y` 去当 z 用，整组几何会被堆到 z≈0 —— 也就是**镜头身后**，
  画面上一个都没有，而代码看起来完全正常。修了两轮才发现。
- **「大」是靠离视轴多近读出来的，不是靠世界尺寸。** 半径 2 的隧道 + 0.85 的视场，
  近处能看见的横向范围只有三四个单位：外景物体放到 3R 之外，最早出现的位置是
  「半径 / tan(视场)」≈ 四五倍半径处 —— 于是它们永远是远处的小碎块。要么贴近管壁，
  要么做得非常大。
- **`fwidth` 驱动的线宽必须封顶 + 按 `fwidth` 淡出。** 掠射角下 `fwidth` 会长到一个
  格子那么宽，此时 smoothstep 让「线」覆盖整块面 —— 地面会变成一块发光的糖。
- **外景物体的材质必须有半球光与常量底色。** 朝向镜头的面拿不到菲涅尔
  （`dot(n, rd) ≈ 1`），细长的管与巨环在远处几乎全是这种朝向，只靠方向光就是黑线。

另外两条：**顶面不能吃侧墙的窗格纹理**（n.y≈1 时 uv 退化，楼顶会长出发亮的窗纹）；
外景的雾要往**被照亮的雾**沉而不是往 `u_bg` 沉，否则远处的管网退成一圈黑链。

另外两条量级上的：**环的径向厚度不能远小于半径**（薄环在屏幕上只是一条掠射带，
只有极窄一段 tanθ 打得到，于是退化成颤抖的细线）；**相机与 SDF 都不该出现大坐标** ——
相机恒在局部原点、SDF 内部加 `u_travel` 还原世界 z，飞到第几百个单位时 float32
仍然够用。

**两条只有真 GL 才能发现的坑**（都实际踩过）：

1. **`u_twist` 声明了、派发了，但 SDF 里没读它** —— uniform 被链接器丢掉、
   `getUniformLocation` 返回 null、`Program.u()` 静默跳过：滑杆能动、画面不动。
   伪 GL 的单测看不见（那边的 location 永远有效）。守卫是 `lab.spec` 里那条
   **「声明了但没被读过」**（`compile-all` 用 `ACTIVE_UNIFORMS` 算出来）。
   修法：扭转**写在 SDF 内部**，不要包在 5 个调用点上。
2. **Apollonian 的 DE 里 `k` 的分子写成了累积量** —— 参考实现
   （iq，ShaderToy `4ds3zn`）里 `k = s / r²` 的 `s` 是**固定参数**，只有 `scale`
   累积。写成累积量会让它指数发散、DE 一路趋零，于是整片空间都判定为命中：
   画面外围是一大块平坦的灰「墙」（y=0 平面被当成表面）。**单帧截图看不出
   公式错**，是「外围为什么有一块平面」这个疑问带出来的。

### 3D 场景（`sdf-geoms.ts` + `sdf-compose.ts` + `scene3d.ts`，2026-11）

几何体从各自的 def 里拆出来了：`SdfGeom`（`name` / `src` / `keys` / `set` / `foldable`）
是**几何的唯一真源**，三个分形与场景共用同一份 `src`。单生成器走
`sdfFrag(geom, { src, call })`，场景走 `scene3d.ts` 运行期拼片段。

- **`main` 只剩一份**，运镜拆成 `{ src, call }` 两截。整块拼在 main **后面**就是
  `no matching function`（报错行指向 main 里那句调用），拼在**前面**才对 ——
  GLSL 要求先声明后使用。
- **uniform 与函数名都要加前缀**（`namespaceGeom`）：两个槽都放 menger 时同名函数
  直接 `redefinition`，同类 uniform 则更坏 —— 能编译、能跑，只是**两个槽共享一个值**
  （「拖一个槽的深度另一个跟着变」）。声明和使用点必须同时改，只改声明等于读到别人
  的值。守卫是 `sdf-scene.test.ts` 的「改名之后没有漏网」。
- 槽的派发靠 `prefixedLocs`（proxy）+ `slotValues`（去前缀）把 `set` 原样复用，
  所以几何体不需要知道「槽」这个概念。
- **首个活跃槽不声明 `u_s<N>_op`** —— 它没有「和谁组合」，没人读它，链接器会丢掉，
  而 `compile-all` 的 dropped 判据会把它报出来（`lab.spec` 直接红）。同理，`op` 参数
  只在「前面有非空槽」时可见。
- **折叠在槽的局部坐标里做**（`q /= zoom` 之后），跨槽折叠是错的。menger 的
  `u_extent` 由槽的 `fold` 经 `SdfGeomCtx.infinite` 驱动，它自己不读 `v.extent`。
- **深度输出的 alpha 必须是 1**。这是**数据**不是覆盖度：吐 0 的话当蒙版时背景读到
  的是层残留（实测一层均匀灰），画面看起来却完全正常。
- **空槽也要拼 `sceneMat` / `sceneBackground`**：`main` 无条件调它们。判断这类错
  只能靠**真编一遍**（拼字符串的单测只看见「占位 SDF 在不在」）。
- **程序名按「槽的 defId 序列」缓存**（`build` 钩子 + `def.build`）。位置 / 缩放 /
  材质 / 组合方式全是 uniform，改它们不该重编；改 defId 必须换名字，否则会复用上一组
  几何的 program。
- 场景**不进** `fractals3d.test.ts` 的「3D 内核家族」那批：它没有单个 SDF，也不含
  `sdfMarch(`，用 `sdfMarchMat`。
- **减法的判据要挑能被证伪的那一种**：挖在物体内部看不出来（格架后面还是料；
  挖在正中心只是掏出一个封闭空腔）。E2E 用的是「大到能盖住整个物体」的槽 ——
  第二槽没进距离场时画面会原封不动。
- 材质型内核加了 `shade` 选项（`sdfKernelMaterial(sd, { shade: true })`）：把
  `sdfShade`（走 `sdfAOMat` / `sdfShadowMat`）一并拼上，场景因此与三个分形共用一套
  着色。那 9 个 uniform 由**调用方**声明（模板里再声明一次就是重复声明），
  `tunnel3d` 不开这一档 —— 它有自己逐材质的着色。

### 引力透镜黑洞（`black-hole.ts`，2026-10）

`realtime` 型，**全家族唯一不做 SDF 步进的 3D 生成器**：每像素沿测地线积分
光子路径，在**体积**盘里累积辐射。视觉目标是 Haskely 的 Gargantua（源自 sonicether
的 Shadertoy `lstSRS`），但**只有做法参照、没有取代码**（见 `CREDITS.md` §2）。

- **积分器是 `a = −1.5·h²·p / r⁵`（rs = 1）**，h² = |p × d|² 守恒。这条式子
  **精确给出光子球 r = 1.5**（圆轨道处 |a| = v²/r 两边相等）。别换成「按偏折角
  累加」的近似：那个做不出「盘的背面被翻到上方」的多重像，而那正是这张图的身份。
- **盘是体积的，不是「穿过 y = 0 采一次面」。** 薄盘版侧视永远是一张纸，也做不出
  视线贴黄道面时的「空集符号」（那个形态依赖盘的上下表面在透镜里都可见）。代价是
  每步都要采噪声，所以盘用「域扭曲 + 三层错频 + 一层刚体颗粒」共 5 次 3D 噪声。
- **步长在盘半径以内收紧到 `0.09 + 0.18·|y|`**，且**必须同时限定半径**：只按 `|y|`
  收紧时，贴着盘面方向飞出去的光线在这一薄层里每步只走 0.05，160 步走不完 8 个
  单位 ⇒ 画面右侧出现一整块没有星空的**黑色楔形**（看上去像「盘投下的影子」，
  其实是被判成「被吞」）。
- **纹理是「域扭曲 + 三层错频 + 一层刚体颗粒」，不是单层 fbm。** 单层的团块
  尺度均匀，放大看是一片豹纹；絮状感来自「大团块里套细丝」—— 先用一层低频噪声
  推开采样坐标，再叠频率比约 1 : 2.7 : 6.8 的三层。
- **密度不许掉到 0**。这是最贵的一课：孔隙在侧视时是好看的絮状（视线在盘里走
  很长，空洞被前后重叠的云填掉），**俯视时视线垂直穿过薄盘，密度为 0 的格子
  直接变成纯透明的黑斑**，整张盘被啃碎、巨物感全无。所以云团之外留一层稀薄的
  底（`0.16 + 0.84·turb`）：它几乎不发光，但仍然吸收、仍然算有物质 —— 俯视时
  读成暗褐薄雾而不是洞。反过来「削掉低端」只能在**侧视专用**的前提下做。
- **差动的角速度指数不能取开普勒的 1.5**：纹理不是流体，长时间强剪切会把细节
  全拉成同心细线（像木纹）。取 0.8~1.1，再单独加一层**刚体旋转的高频颗粒**
  （角速度与半径无关）—— 差动层给螺旋结构，刚体层保证「盘在转但看得见颗粒」。
- **颜色不是一条从内到外的渐变。** 同一半径上要有淡金与淡紫交错（参考图里那
  是高温星际物质的色相抖动），所以色相由一个**独立的低频场**给，径向只负责
  三段：内缘白热（几乎纯白）、中带半透明微光、远端暗紫不发光。按「温度 →
  色阶」写会得到一条均匀的橙金带，怎么调都不像。
- **温度按 `r / diskIn` 归一 ⇒ 内缘恒为白热**。所以「把盘缩成细环」不会让它变暗，
  反而更亮。E2E 里要给「盘真的在发光」做对照，只能压 `bright`。
- **色阶保留色相，只在最后混掉 18% 的 luma**。混到 50% 会得到一张灰阶照片
  （实测被当成「黑白渲染」）；「低饱和」指的是亮部不黄到发土，不是没有颜色。
- **E2E 不能用 `lit / total`**：背景是星空 + 银河，每个像素都非零（实测占比 ≈ 1.0）。
  判据用 `mean` / `spread` 与「关星空 / 压暗盘」两个单向绝对差。
- **相机是球坐标 + 滚转 + 移轴，不给裸 XYZ**：裸位置允许把相机塞进视界（整幅全黑，
  无提示）；「不在画面中心」由 `shiftX / shiftY` 解决。`orbit` 出厂 0 —— 先构图
  再决定要不要转。缺省 `pitch = 2°` 贴黄道面：这个角度才看得见盘的**实际厚度**，
  俯视时看到的「厚」是透镜把盘背面放大出来的。
- **星点尺寸按 `u_fov / u_resolution.y` 换算**：方向空间里的固定尺寸会随 `intRes`
  变粗变细 —— 而 `intRes` 是性能档位，不该改变画面。
- 盘外溢的柔光是**解析的、压扁 2.4 倍**的辉光（单 pass 没有邻域），并且跟着
  `roll` 转。做成圆形会在盘的上下方留下一片无从解释的灰雾。

### 体积烟雾（`smoke.ts`，2026-10）

`realtime` 型，**全家族第一个支持透明底的生成器**（协议见下面「透明背景」一节）。
沿射线固定步长前向累积 + Beer–Lambert；`浓度` 是光学厚度、`采样精度` 是步数。

**调节过程中有四次「改了但看起来没变」，每次都是同一个病根：某一项被积分平均掉了。**

1. **密度不能是「噪声 × 包络」。** 那样轮廓永远勾着解析锥，怎么调都是一根几何柱。
   写成「**包络只移动噪声的阈值**」：阈值在 0.42~0.56（包络中心）到 0.92（包络外）
   之间移动，而 `fbmS` 归一化后的 p99.9 只有 **0.81** —— 到不了 0.92，所以外面
   一粒沙都没有，边界却由噪声自己切出来，是碎的。
2. **阈值必须按实测分位数定，不能凭直觉取 0~1。** 实测（屏上读数）：
   `fbmS` p50 0.51 / p90 0.66 / p99 0.76 / p99.9 0.81；`plumeEnv` p90 只有 **0.41**
   （它是锥形 × 竖直衰减 × 耗散三个因子的乘积）。凭直觉拿包络插值阈值 =
   把切点抬到噪声 p99 之上 ⇒ 整个体积几乎没烟（`swirl=0` 时屏上只剩一个点），
   而且不报错。**换 fbm 的归一化方式或阶数都要重测这一组。**
3. **体积在 z 上只能占一两个噪声 cell。** 全 3D 时 40 次采样把密度积分成常数
   （CLT）—— 实测亮度范围从 `steps=1` 的 28..161 塌到 `steps=8` 的 28..86，
   再往上加步数毫无变化。压成 2.5D 之后 alpha 还留着横向结构，立体感改由光照提供。
4. **光照必须是沿光方向累加的光学厚度，不能只采一次邻居。** 单次邻居采样同样被
   40 次积分平均成常数。现在走三步 `fbmS(q + lightDir*k*0.5)`，`lightDir` 含 z 分量。

**代价与副作用（都是有意换来的）**：

- 轮廓 = 「整条射线都空」的区域 = 阈值在 z 上不变时的一条**解析等值线**。
  阈值里叠了两层沿 z 相干的正弦（周期 ~2.6 / ~1.2）来破这个，别再删 ——
  删掉后 `swirl=0` 会让烟退化成两片饼干模压的平面剪影。即便如此，
  旋流归零后覆盖度仍会从 10.9% 掉到 7.3%（每个深度看到的噪声都一样了）。
- `plumeEnv` 量的是**水平距离**，在屏幕平面里旋它不是对称操作：包络只吃 1/3 的
  旋流角，全吃的话轮廓会随 z 扫出一片扇形，一个美学参数顺手改掉体积。
- **逐像素 z 抖动会变成一层洗不掉的细颗粒**（最前面那个采样在像素间挪位置，
  采样点上的包络跟着变）。现在固定 `jitter = 0.5`。
- `tau` 的常数 26 必须与 `d` 的量级匹配：`d` 是阈值切出来的尾巴（典型 0.05~0.2），
  系数取小会让「浓度推到 1 还是 alpha 0.1」，用户会以为滑杆坏了。

**缩略图必须强制纯色底**：出厂是透明底，`catalog.ts` 里 `bgMode: 'solid'` 不能省，
否则菜单预览浮层里是一片空白。

**怎么验**：合成链 `readPixels` 读回来的像素不干净（中间层污染，曾误判成采样平面
的横向条带）。改成页面里直接 `import` def、自建 canvas + 程序 + 全屏三角渲一帧。
把 `fragment` 在 `void main()` 处截断、拼一个只输出单层 `d`/`env0`/`fbmS` 的
`main`，就能把密度场单独切出来看 —— 判断「是密度场没结构」还是「被积分抹平」，
靠猜会连错四次。

性能（40 步 / 3 阶 / 自阴影开）：480p **0.88 ms**、720p **1.48 ms**、1080p **3.32 ms**；
720p 关自阴影 1.13 ms，720p 拉到 96 步 2.82 ms。`edge` 模式覆盖整屏，
包络剪枝失效，同分辨率约贵一倍。

### 体积云（`volumetric-cloud.ts`，2026-11）

`realtime` 型：射线与一层**无限大的水平云板**解析求交，板内固定步长累积
（单次散射 + Beer–Lambert），每步朝太阳再走四步估光学厚度。噪声走 `nzFbm3`。
相机眼恒在原点，**「云在头顶还是在脚下」由 `altitude` 的正负表达** —— 给裸位置
会把镜头塞进云里，那时整幅只剩一片白、且没有任何提示。

五条实测才会发现的：

1. **`soft` 是 0..1 的滑杆，带宽必须按 fbm 的标准差换算**。直接拿 0.3 当
   smoothstep 的带宽（≈ 3σ）会把每朵云糊成半透明的雾，整幅变成一层脏灰。
2. **自阴影要用比云体更松的阈值**。用同一条硬阈值去采光线上的四个点，四处
   全是 0 ⇒ `od = 0` ⇒ `lit ≡ 1`：「自阴影开了跟没开一样」，而参数、派发、
   编译全都正常。
3. **明暗不能直接拿相位当亮度**。相位只在朝太阳时接近 1，背光那一侧整幅会压
   在混色区间的中段 —— 实测每朵云都是同一种浅灰（像石膏）。相位只做窄倍率。
4. **逐像素抖动是必需的**：步长均分会让采样点落在固定的几层壳上，掠射角下
   云体边界与这些壳相交 ⇒ 一圈圈同心的细横纹。抖动把它换成细颗粒 ——
   两者是同一件事的两面，别只为颗粒把抖动关掉。抖动取 `gl_FragCoord` 的
   hash，是像素的纯函数，确定性不受影响。
5. **远段先淡出，再加步数**：掠射射线的跨度能到视距那么长，那一段采样间隔
   最大、颗粒最明显。`haze` 从 0.25·视距就开始淡，比把步数翻倍便宜。

成本（48 步 / 默认参数 / 含合成与一次读回的固定开销）：内部 480 → **4.3 ms**、
720 → **5.0**、1080 → **7.6**；1440p 按像素推 ≈ 11 ms（4070 laptop 实测口径）。
**超了就降步数、不要降分辨率**（`intRes` 默认 `auto`）。

### 地平线（`horizon.ts`，2026-11）

掠飞地形走 `sdfKernelMaterial`（材质号 0 陆 / 1 水），镜头恒在局部原点，
世界靠 `horizonTravel()` 沿 -z 流过它。五条只在高度场上出现的失效：

- **归一化 fbm 不能直接当高度**：它的标准差只有 0.1，画面会退化成一张带
  等高线的平板。高度是位移，先过 `nzCentered()` 把动态范围拉开。
- **`p.y - h` 不是欧氏距离**：`|∇h| > 1` 时过估，步进会跨过山顶。SDF 乘
  0.42 再叠 `stepScale = 0.5`。台地用连续阶梯（`floor + smoothstep(fract)`），
  裸 `floor` 会在台阶边把距离场撕开。
- **远处高度场必须压平**：近水平射线往前走时 `p.y - h` 不单调，h 抬得比
  射线快就会在天空里判成命中，长出一排漂浮薄板 —— 雾盖不掉，命中距离
  并不远。按局部 z 渐隐到水面。
- **朝上的射线不 march，未命中的向下射线要补一次解析求交**：相机恒在地形
  上界之上，掠射射线在 72 步里走不完视距，逐像素在「命中 / 未命中」之间
  跳。远处已压平成水面，所以补到 `y = seaLevel` 是几何上成立的。
- **水面反射不能吃满**：掠射角下水面与天空同色，露出水面的岛就像悬空板子，
  留 28% 固有色当底座。线宽不用 `fwidth`（命中判定是非一致控制流），按
  `hit * u_fov / u_resolution.y` 解析给，并按同一条量早早淡出，否则网格与
  等高线在陡坡上挤成百叶窗状密纹。

风格是 JS 侧 `HORIZON_STYLES`（6 色 + 三组 vec4 共 12 个连续量），shader
没有风格分支。`lab.spec` 的 dropped-uniform 判据要求 12 个通道全部被读到 ——
漏一个就是「选项能切、那个维度永远不动」。

### 透明背景（`bgMode`，2026-10）

烟雾之外还有 **22 个**生成器支持透明底：5 个 bake（rule110 / bifurcation / lsystem /
chaos-game / dla）、10 个 sim（game-of-life / langtons-ant / reaction-diffusion /
brians-brain / cyclic-ca / sandpile / snowflake / lenia / wireworld / buddhabrot）、
3 个 3D（menger / mandelbulb / apollonian）、以及 `grid` / `kleinian` /
`kinetic-shapes` / `volumetric-cloud`。

- **参数与派发各只有一份**：`bgModeParam()` 造参数、`bgModeOf()` 读值
  （都在 `shader-lib.ts`），`u_bgMode` 由 `AlgoRuntime.resolve` **统一派发**
  （0 = 纯色 · 1 = 透明）。def 自己不要再写一遍 —— 二十个文件各写一遍就等于
  留二十个「选了透明什么都没发生」的静默失效点。`smoke` 原本自带一份，
  而且取值是**反的**（0 = 透明），并入时最容易翻车的地方就在那里。
- **覆盖面是「墨 + 底」那一族**：有 `colorBg`（bake / sim）或 `bg`（3D）的生成器。
  `gradient` / `bars` / `mandelbrot` / `newton` / `lyapunov` / 五个 `scene-*` **刻意不给**：
  它们整帧都是内容，没有「哪一块是背景」这回事。硬造一个（比如按亮度取 alpha）
  会在边界留下一圈脏边 —— 比没有更糟。
- **必须吐直通 alpha**：`vec4(墨色, 覆盖度)`，**不是** `vec4(mix(底, 墨, 覆盖度), 覆盖度)`。
  合成链是直通（非预乘）alpha（`engine/placement.frag.ts`），半覆盖的像素再乘一次
  alpha 等于把底色又画了一遍 —— 表现是边界上一圈深色轮廓。所以自定义 tint
  （RD / cyclic）还要多算一个「不掺底色的墨色」。
- **缺省一律 `solid`**（`smoke` 除外，它出厂就是透明）。理由不是「保住老工程」：
  `colorBg` 是这一族的正常参数，缺省透明会让它**默认失效**，而缩略图在浅色菜单
  底板上会糊成脏灰（`catalog.ts` 给 smoke 强制 `solid` 就是那么踩出来的）。
  透明模式下底色参数由 `bgColorVisible` 藏起来 —— 不留「拖了没反应」的控件。
- **`bgMode` 必须进 `volatile`**：它只在 reveal / tint 里读，不进 `bake()` / `create()`。
  漏了就是「切一下透明，跑了几千步的模拟从头重放」。
- 守卫：`tests/unit/algo-uniforms.test.ts`（有参数就必须真的读 `u_bgMode`；
  它列在 `RUNTIME_OWNED` 里，不算「声明了没写」）+ `tests/e2e/algo-alpha.spec.ts`。
  ⚠️ **E2E 只能测「下层透出来」**：渲染上下文是 `alpha: false`（`engine/kit.ts`），
  `readPixels` 的 A 通道**恒为 255** —— 直接断言 alpha 等于什么都没测。
  那里用的判据是：透明 + 下层纯红 ⇒ 必须数得到红像素；纯色 + 下层纯红 ⇒ 一个都不许有。

### Lenia 的卷积（`sim-util.TorusField`）

- **环状核在 `width=0.15` 下实际是**整个圆盘**：峰值在 d=0.5，而 d=0 处权重仍是
  `exp(-5.6) ≈ 3.8e-3`，远大于 `eps=1e-4`。实测 R=10 → 317 抽头 = πR²。所以成本是
  Θ(n²·πR²)（R 从 10 调到 16 就是 2.5 倍），**调 `eps` 一点用都没有**。
- `TorusField` 给场加一圈 R 宽的 halo，内层循环只剩一次乘加、零分支：
  112²/R=10 实测 **7.82 → 3.80 ms/次（2.06×）**，且**逐位相同**（`maxDiff === 0`）。
  halo 最容易错的是**四个角**（上下两条 halo 只复制中段、不连左右一起复制），
  有单测与朴素回绕实现逐位对拍。
- 偏移表按核预计算 —— 每步重建会把 2× 的收益吃回去。
