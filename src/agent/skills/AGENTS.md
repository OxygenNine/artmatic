# src/agent/skills/ —— 内置技能（SKILL.md）

**何时读我**：要新增 / 修改一份技能，或者动索引与读取逻辑（`registry.ts` / `parse.ts`）。

格式是 Agent Skills 开放标准（agentskills.io）。我们只实现**可移植核心**：
`SKILL.md` + `references/`，三级披露，`name` / `description` 两个必需字段。

```
builtin/<name>/SKILL.md              必填，name 必须与目录同名
builtin/<name>/references/<file>.md  可选，正文里点名引用
```

## 与 `help(topic)` 的分界

这是本目录唯一的架构问题，答错了会得到两套互相抄的文档。

| | `help(topic)` | 技能 |
|---|---|---|
| 内容 | **一个子系统的 API 真源**（uniform 列表、字段表、单位） | **跨工具的做法**（步骤顺序、参数取哪几个、怎么自检、哪里会静默失败） |
| 真源 | 由常量拼出（`plugin-spec.ts`），跟着代码走 | 手写散文，跟着经验走 |
| 形态 | 一张参考表 | 一篇流程 |

判据：如果这段内容在代码里加一个字段就该跟着变，它属于 `help`（而且最好是拼出来的）；
如果它是「先做什么、再做什么、看什么判断对不对」，它属于技能。

**不要在技能里抄参数表**：抄了就会在下次加参数时漂，而模型看不出那份表过期了。

## 写一份技能

1. `mkdir -p builtin/<name>`，写 `SKILL.md`，`name` 与目录**逐字相同**。
2. `description` 是**唯一**决定「要不要读这份」的文本。写清楚 what + when，第三人称，
   带上用户真会说的词（`卡点`、`poster`、`too dark`）。**≤ 480 字符** —— 它对每条会话
   常驻上下文，超了就该拆或删。
3. 正文 ≤ 200 行。结构固定：先一句「这件事的判断标准」，然后编号步骤，最后 `## Traps`。
   超过 200 行说明里面有一半是参考资料 → 挪到 `references/`。
4. `references/` **只有一层**，文件名在正文里写成 `references/<file>.md`
   （单测会检查它真的存在）。
5. 英文。这些文字是给模型读的指令，与工具描述同语言；界面文案走 i18n。

## Traps 那一节写什么

只写**会静默失败**的东西：写错的参数名被拒还是被忽略、单位差 57 倍、默认值让画面
不变、两个字段互斥、工具不报错但什么也没做。这些正是模型无法从工具描述里推出来的。

不要写「要注意质量」「多检查」这类没有判据的句子。

## 别做的事

- **不要在技能里写第二份工具清单**。工具的权威描述在 `tools.ts`；技能只引用名字。
- **不要承诺效果已经可见**。没渲染过就说「应该」。
- **不要在技能之间互相引用**。要复用就抽成 `references/` 里的公共文件，或者承认它们是两件事。
- **不要为了「以后可能有用」加技能**。一份没被 `read_skill` 调过的技能是纯成本：
  它的描述对每次请求都在计费。加之前先问「这类任务到底出现过几次」。

## 守卫

`tests/unit/agent-skills.test.ts`：frontmatter 解析、目录名一致、描述长度、正文行数、
`references/` 链接存在性、索引不含正文、系统提示带索引。改名/挪目录时它会先红。

加载期问题（`SKILL_ISSUES`）不抛异常也不影响启动：坏技能被排除在索引之外，
测试点名。这是刻意的 —— 一份写坏的技能不该让整个应用起不来。
